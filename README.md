# Identifiability and Gradient-Based Bayesian Inference for an Entrained Two-Process Sleep Model

Computational work supporting the University of Bristol MSc Data Science thesis of the same title.

The project studies Bayesian parameter inference for an entrained two-process sleep–wake model observed through epoch-level sleep/wake labels. The `twopm` package implements a hard-switch reference simulator, a differentiable smooth-gate model (Diffrax), the observation likelihood, and NUTS inference (NumPyro). Scripts and stored artifacts cover transition-map identifiability, profile likelihood, gradient validation, hard-versus-smooth validation, sampler diagnostics, repeated synthetic recovery experiments, and the four thesis figures. All analysed data are synthetic and are generated by the repository code using the model, prior and experimental settings in `config/model.yaml`.

## Repository structure

```
config/     model.yaml — model, prior, numerical and design settings
src/twopm/  the package: model, likelihood, inference, sampling, summaries
scripts/    experiment and analysis entry points
tests/      pytest suite
figures/    one directory per thesis figure (make_figure.py + final PDF)
runs/       stored NUTS runs RUN-001 … RUN-014 (manifests, logs, selected posteriors)
docs/       stored numerical artifacts (JSON / NPZ / CSV) used by scripts and figures
```

`docs/` holds numerical outputs, not documentation.

| Module | Contents |
| --- | --- |
| `hard_switch.py`, `analytic.py`, `circadian.py` | hard-switch simulator, analytic bout durations, circadian thresholds |
| `soft_gate.py` | smooth-gate model, Diffrax integration, transition matching |
| `generative.py`, `observation.py`, `likelihood.py` | synthetic recordings, observation model, log-likelihood |
| `inference.py`, `sampling.py` | NumPyro model and priors, sequential NUTS runner |
| `posterior_summaries.py` | entrained transition-time solver |
| `gradients.py`, `predictive.py`, `config.py`, `plotting.py` | gradient check, prior predictive, config loader, exploratory plots |



## Design principles for the repository structure

* **Separation of concerns:** library code in `src/twopm/`, one script per experiment in `scripts/`, tests, figures and stored artifacts in their own directories.
* **Single responsibility:** one module per model component, one script per artifact.
* **DRY:** scripts and figures import the library; figures share `thesis_style.py`.
* **Single source of truth:** all settings in `config/model.yaml`, overridden by flags, never by editing code.
* **Provenance and immutability:** every run records config hash, source hash, git commit and seed; run directories are write-once.
* **Independent verification:** hard-switch and smooth-gate models share no integration code.
* **Reproducibility:** fixed seeds, 64-bit JAX, pinned dependencies.
* **Fail fast:** figure and analysis scripts validate inputs before doing work.
* **Restartable jobs:** long campaigns skip completed replicates.

Fast scripts (seconds each):

```bash
python scripts/check_gradient.py
python scripts/recompute_identifiability.py
python scripts/test_entrained_gate_fidelity.py
python scripts/generate_hard_recording.py
python scripts/compare_hard_soft_profiles.py

```

These overwrite the stored file of the same name in `docs/`. The committed versions carry a few extra annotation fields that are not regenerated.

Profile likelihood campaign (input to Figure 2):

```bash
python scripts/profile_likelihood.py \
  --parameters chi_wake chi_sleep threshold_gap amplitude \
  --chi-wake-min 8 --chi-wake-max 40 \
  --chi-sleep-min 1.5 --chi-sleep-max 10 \
  --threshold-gap-min 0.25 --threshold-gap-max 0.75 \
  --amplitude-min 0.02 --amplitude-max 0.25 \
  --grid-size 21 --max-fev 1000 \
  --retained-hours 24 --burn-in-hours 48 \
  --seed 31416 --mle-nll-max 15 \
  --profile-dir docs/profile_campaign \
  --output docs/profile_campaign.json
```

`scripts/profile_hard_chi_wake.py` uses its defaults and reads `docs/hard_generated_recording.npz`. It resumes from any per-point files already in `docs/profile_hard/`, so clear that directory for a clean recompute. `docs/profile_chi_wake_partial.json` is a stored artifact with no separate recompute script.

Other scripts in `scripts/` produce the remaining `docs/*.json` artifacts. Use `--help` where available.

## Running NUTS inference

`scripts/run_mcmc.py` writes `runs/<RUN-ID>/manifest.json`, `iterations.csv`, `timings.json`, `posterior.nc` and (when captured) `adapt_state.npz`. Run IDs are write-once: the script refuses an existing `runs/<RUN-ID>/`. See `--help` for options.

RUN-014 settings, with a new run ID:

```bash
python scripts/run_mcmc.py \
  --run-id RUN-014-repro \
  --title "Four-chain R-hat on the entrained fibre" \
  --question "Four-chain reproduction of RUN-014" \
  --design entrained \
  --duration 24 --burn-in 48 \
  --chains 4 --warmup 200 --draws 100 \
  --max-tree-depth 7 --dense-mass \
  --fix-misclassification 0.01 \
  --seed 0
```

The launchers `scripts/launch_run014.sh`, `launch_run008.sh`, `launch_sbc8.sh` and `launch_profile4_then_run014.sh` record the original settings. They are macOS-specific (`caffeinate`, `zsh`, `pmset`) and reuse the original run IDs.

## Recovery replicates

This eight-replicate experiment was originally intended as an SBC check. The label-error rate \(\lambda\) was initially inferred, but was later fixed at 0.01 to test whether uncertainty in the observation model was causing the very small NUTS step sizes seen in earlier runs. It was not, so the fixed value was kept for the final fits. The prior-predictive generator, however, still sampled \(\lambda\) from its prior. This meant the datasets were not generated from exactly the same model that was fitted, so the usual SBC rank-uniformity result no longer applied. The experiment is therefore treated as a repeated recovery check rather than formal SBC.

To inspect or reanalyse the committed campaign, use the eight files in `docs/sbc/` (`scripts/analyze_sbc8.py` and Figure 4 read that directory).

To rerun the campaign from scratch, write to a fresh directory so the committed replicates are neither skipped nor overwritten (`results/` is git-ignored):

```bash
python scripts/run_sbc_replicates.py \
  --n-replicates 8 --start-index 0 --seed-base 20260808 \
  --warmup 200 --draws 100 --max-tree-depth 7 \
  --output-dir results/sbc_repro
```

The script creates the directory and skips any replicate file already present in it, so an interrupted rerun can be restarted with the same command. `scripts/analyze_sbc8.py` and `figures/fig4_repeated_recovery/make_figure.py` read only `docs/sbc/`; to analyse a rerun, copy its eight `replicate_NNN.json` files into `docs/sbc/` (or point those two scripts at the new directory).

## Results versus recomputation

This repository contains the model, inference and validation code, the configuration, and the stored run artifacts underlying the thesis. The core analyses — model simulation, gradient validation, identifiability metrics, profile likelihood, NUTS inference, the repeated-recovery campaign and the four thesis figures — can be recomputed or regenerated from the scripts provided. A number of secondary diagnostics reported in the thesis were computed at finalisation directly from the stored artifacts and do not have standalone scripts.

Figures and lightweight analyses run from stored artifacts. Full NUTS runs, profile campaigns and recovery replicates take hours on a laptop CPU. Their outputs are retained so downstream results can be reproduced without rerunning them.

## Configuration

`config/model.yaml` holds model parameters, priors, solver settings, the observation model, experimental designs (`entrained`, `weak_forcing`) and validation tolerances. `run_mcmc.py` applies command-line overrides on top of it and records the effective configuration hash in the manifest.
